**Key points:**
- Promotional content events in Play Console can now include an optional animated asset, on top of the usual static image.
- A new multi-country scheduling option lets one event run different start and end dates for different groups of countries.
- All start dates in a multi-country event must sit inside the same calendar quarter. Spanning quarters needs separate events.
- A multi-country event still counts as one quota item, no matter how many country groups it has.

Google Play's promotional content tool, often called LiveOps, just got two real additions. One is visual. One is about timing. Both change how a single event can reach different markets.

## The animated asset addition

Promotional content events used to run on a single static image. Now, an event can carry an optional animated asset alongside it. The goal is simple: catch more attention in a Play Store feed full of static art. This is optional, not required. A static-only event still works fine. But an animated asset gives an event a real edge in a crowded feed, especially for a game or app running a limited-time offer.

## Multi-country scheduling, and its one real limit

| What you can do | What you can't do |
|---|---|
| Set different start and end dates per country group | Span two different calendar quarters in one event |
| Group countries that should share the same timing | Add unlimited quota items for extra country groups |
| Run one event across many markets at once | Skip the quarter-boundary check silently |

The bigger change is scheduling. Before, one event meant one schedule everywhere. Now, you can group countries and give each group its own start and end date. A launch that should hit Japan first, then the US a week later, can now live inside a single event instead of two.

There's a real catch, though. Every start date across every country group must fall inside the same calendar quarter. Try to set a date outside that quarter, and Play Console blocks it with an error. A campaign that genuinely needs to run across two quarters still needs two separate events, one per quarter, not one event stretched across both.

The upside: a multi-country event, no matter how many country groups it has, only uses one quota item. That's a real saving over the old approach of creating a new event per country just to stagger timing.

> **Real-world scenario:** A mobile game team wanted to launch the same seasonal event in Japan a week ahead of the rest of the world, to gather early feedback before the wider push. In the old system, that meant either one shared schedule for everyone, or burning two separate quota items on two events. With multi-country scheduling, they grouped Japan on its own timing and grouped the remaining regions together in the same event. Both schedules sat inside the same quarter, so one event covered the whole rollout, using just one quota slot.

## What to actually do about it

1. **Add an animated asset if your event has real visual movement to show.** A gameplay clip or a simple motion graphic can stand out more than a static image in a crowded feed.
2. **Group countries by real timing needs, not by habit.** If two regions genuinely need different dates, multi-country scheduling now handles that in one event.
3. **Check your quarter boundaries before you build the schedule.** A launch that crosses a quarter line needs two events from the start, not one you'll have to split later.
4. **Don't assume more country groups costs more quota.** It doesn't. Use that to consolidate events you'd previously split just for scheduling reasons.
